CORRECCION 1 — EVITAR EL ERROR DE PAGINACION

Problema: app/routers/patients.py:50 solo exige page >= 1.
app/services/patients.py:77 calcula OFFSET = (page - 1) * page_size.
page=9223372036854775808 produce un valor que PostgreSQL no puede usar como
OFFSET; la API devolvió 500. OFFSET es cuántas filas se saltan al paginar.

Dónde: en tu editor, abre app/routers/patients.py.
Busca esta línea:

    page: Annotated[int, Query(ge=1, description="Página, comenzando en 1")] = 1,

CAMBIO: reemplázala por esta única línea:

    page: Annotated[int, Query(ge=1, le=100000, description="Página: 1 a 100000")] = 1,

Por qué: le fija un máximo. 100000 es una política propuesta, no un número de
la rúbrica. Con page_size máximo 100 mantiene OFFSET dentro de un rango válido.
No garantiza consultas rápidas con grandes volúmenes; eso requiere otra medición.

CAMBIO EN PRUEBAS: abre tests/test_patients.py. En la lista de casos de
la función test_bad_filters, agrega estos dos diccionarios:

    {'page': 100001},
    {'page': 9223372036854775808},

CORRECCION 7 — AGREGAR Y PROBAR CI/CD

CI = construir, probar y analizar cada cambio. CD = desplegar la imagen aprobada.
Runner = equipo que ejecuta las tareas de GitHub; GHCR = registro de imágenes.
Tag = etiqueta que identifica la versión de una imagen.
La pauta exige los cuatro: Build, Test, Security Scan y despliegue de imagen con tag.

Solo un push a main intenta publicar/desplegar. Las otras ramas se verifican.

ANTES DEL PRIMER PUSH, configura en GitHub:
